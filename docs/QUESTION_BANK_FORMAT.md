# 刷题小助手：题库格式指南（1.0）

本指南对应本包的 `assets/engine.js` 和 `docs/question-bank.schema.json`。浏览器加载题库时与本地校验工具使用同一套校验规则。无需服务器、数据库或打包构建，网站可以直接在 GitHub Pages 上运行。

## 1. 文件组织与加载方式

| 路径 | 职责 |
| --- | --- |
| `data/catalog.js` | 顶部课程下拉菜单的课程ID及顺序 |
| `data/courses/<课程ID>.js` | 单门课程的完整题库 |
| `index.html` 中的题库 script 标签 | 实际加载每门课程的题库文件 |
| `assets/engine.js` | 校验格式、单选/多选判分、选项乱序及章节题型计数 |
| `assets/app.js` | 课程切换、练习界面、错题本与学习统计 |
| `templates/new-course.json` | 可编辑的纯JSON模板 |
| `templates/new-course.js` | 可直接复制为网页题库的JS模板 |
| `data/courses/format-demo.js` | 已注册的完整格式示例，含六种题型与2道X型题 |
| `tools/validate-banks.cjs` | 本地批量校验工具，无第三方依赖 |

每个题库JS只做两件事：初始化统一容器，并把课程对象存入对应ID。

```javascript
window.QUIZ_BANKS = window.QUIZ_BANKS || {};
window.QUIZ_BANKS["new-course"] = {
  "schemaVersion": "1.0",
  "course": {
    "id": "new-course",
    "title": "新课程",
    "description": "新课程的介绍",
    "version": "1.0.0"
  },
  "chapters": [
    {"id": "chapter-1", "title": "第一章"}
  ],
  "questions": [
    {
      "id": "q1",
      "chapterId": "chapter-1",
      "type": "A1",
      "num": 1,
      "stem": "以下哪个数是偶数？",
      "options": [
        {"id": "A", "text": "1"},
        {"id": "B", "text": "2"},
        {"id": "C", "text": "3"}
      ],
      "answers": ["B"],
      "explanation": "2是本题唯一的偶数。",
      "source": "示例资料第1页"
    }
  ]
};
```

JS包装的目的是避免通过fetch读取本地JSON，因而解压后也能直接打开index.html。纯JSON是编辑和校验格式；仅把JSON上传到目录，不会自动成为可选课程。

## 2. 字段总表

下表未标为可选的字段全部必填。对象不接受表中未定义的字段，避免拼写错误被静默忽略。

### 2.1 顶层对象

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `schemaVersion` | 字符串 | 固定为 `"1.0"`，不能写成数字1 |
| `course` | 对象 | 课程元数据 |
| `chapters` | 数组 | 至少一个章节，按界面显示顺序排列 |
| `questions` | 数组 | 至少一道题，按原始出题顺序排列 |

题目总数、各章节题数、各题型题数均自动计算，不需要手写total字段。

### 2.2 course对象

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | 字符串 | 课程唯一ID，与catalog.js和JS容器键完全一致 |
| `title` | 字符串 | 非空课程名，显示于顶部下拉菜单 |
| `version` | 字符串 | 非空版本号，建议使用1.0.0、1.0.1等 |
| `description` | 字符串，可选 | 首页课程简介，可以为空字符串 |

课程ID、章节ID、题目ID、组ID统一使用：1–80位英文字母、数字、下划线或连字符，第一位必须为字母或数字。例如 `preventive-medicine`、`chapter-1`、`q88`。不允许空格、中文、引号或斜杠。建议用有意义的小写ID。

课程ID决定本地记录的存储命名空间。已经开始使用的课程不要随意改ID，否则会被当成另一门课程。

### 2.3 章节对象

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | 字符串 | 同课程内唯一，题目通过chapterId引用 |
| `title` | 字符串 | 非空章节名称，可为中文 |

允许章节暂时没有题目，此时题数为0；但整门课程必须至少有一道题。章节数组顺序就是首页与统计页的章节顺序。

### 2.4 题目对象

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | 字符串 | 同课程全部章节内唯一；保存历史记录时使用 |
| `chapterId` | 字符串 | 必须引用本课程已定义的章节 |
| `type` | 字符串 | 只能是A1、A2、A3、A4、B、X，区分大小写 |
| `num` | 正整数 | 原资料中的题号，用于定位，不承担唯一标识职责 |
| `stem` | 字符串 | 非空题干，不要把选项或答案粘入其中 |
| `options` | 数组 | 2–10个选项，按照原资料的显示顺序排列 |
| `answers` | 字符串数组 | 单选必须恰好1个；X型至少2个；必须全部引用现有选项ID，不得重复 |
| `groupId` | 字符串，可选 | 同章节内的题组标识；不要给不同题组重复使用 |
| `sharedStem` | 字符串，可选 | 共用病例或材料，显示在题干前，可使用换行 |
| `explanation` | 字符串，可选 | 提交后显示的解析 |
| `source` | 字符串，可选 | 原资料名称、页码或核对备注，供题库维护查询；不作为外部接口 |

题号可以在不同章节重新从1开始，也可在同一章节重复，但建议避免让读者混淆。题目ID不可重复。更新题干或答案时尽量保留ID；删除后也不要把旧ID分配给另一道无关的新题。

同组题必须采用相同的type和sharedStem文本。组作用域是“当前课程＋章节”，不会与其他课程或其他章节冲突。B型题同组选项必须连同顺序完全一致。没有共用题组的题可以省略groupId。

### 2.5 选项对象

```json
{"id": "A", "text": "选项的完整文字"}
```

- `id`：大写A–J的单个字母，在同题内不可重复。
- `text`：非空纯文本，不要在开头再写一次“A.”等选项标签。
- ID是稳定的源选项标识，数组顺序决定原始呈现顺序。通常按A、B、C排列。
- 选项数量不必固定为5，支持2至10项。显示字母和键盘快捷键会自动适配。
- 不要用HTML标签表示上下标。可用Unicode字符，如 `CO₂`、`10⁻⁵`、`μPa`；注意单位、正负号和指数不能省略。

## 3. 六种题型及判分

| type | 题型 | 交互 | answers示例 |
| --- | --- | --- | --- |
| A1 | 单项选择题 | 点一个选项即判分 | `["A"]` |
| A2 | 病例单项选择题 | 点一个选项即判分 | `["C"]` |
| A3 | 共用题干单选题 | 共用材料＋本题独立选项 | `["B"]` |
| A4 | 病例发展单选题 | 共用材料＋本题独立选项 | `["D"]` |
| B | 共用备选答案单选题 | 同组复制相同选项；每题单选 | `["A"]` |
| X | 多项选择题 | 先选/取消多个选项，再提交 | `["B", "D", "E"]` |

除X型外，系统均按单选题处理。X型题要求正确选项至少两个，支持全选均正确的题。选中的集合与正确答案集合完全相同才判正确：顺序不影响判分，漏选、多选、错选均判错，不设部分得分。

### 3.1 X型题完整例子

```json
{
  "id": "multi-1",
  "chapterId": "chapter-1",
  "type": "X",
  "num": 2,
  "stem": "请选择所有偶数。",
  "options": [
    {"id": "A", "text": "1"},
    {"id": "B", "text": "2"},
    {"id": "C", "text": "3"},
    {"id": "D", "text": "4"},
    {"id": "E", "text": "6"}
  ],
  "answers": ["B", "D", "E"],
  "explanation": "2、4、6均为偶数。"
}
```

未提交之前：允许反复选择和取消，不判分、不写入错题本、不更新学习统计。“下一题”禁用，“显示答案”隐藏。按提交按钮或主动按Enter提交后才判分。尚未选任何选项时，提交按钮禁用；空提交不计错。

离开题目再返回时，本轮未提交的选择仍保留。结束本轮、重新开始、刷新网页或切换课程后未提交的草稿不恢复；已提交的结果已经保存。X型题不能通过空格“显示答案”绕过提交。

### 3.2 普通模式与快刷模式

| 题型 | 普通模式 | 快刷模式 |
| --- | --- | --- |
| A1/A2/A3/A4/B | 选择后判分，停留，手动下一题 | 答对立即下一题；答错停留，手动下一题 |
| X | 点击提交后判分，停留，手动下一题 | 点击提交后，正确立即下一题；错误停留，手动下一题 |

快刷不设置延迟跳题定时器，因此答错、切换页面或切换课程后不会发生延迟跳题。最后一题答对且处于快刷模式时直接进入结果弹层。

单选题保留“显示答案”，查看答案按未掌握计入错题，不会被快刷自动跳过。已提交的题不能在本轮重复判分。错题重刷遵循首页当前选择的模式。

## 4. 共用材料与B型题组

A3/A4建议为同组每题复制完全相同的sharedStem，并设置相同的groupId；每题有各自的options和answers。系统每题都展示共用材料，因此题目乱序后也不会失去病例上下文。组题不强制在乱序队列中连续出现。

B型题示例，省略与常规题相同的其他字段：

```json
[
  {
    "id": "b1", "chapterId": "chapter-1", "type": "B", "num": 3,
    "stem": "1+1的结果是？", "groupId": "sum-group",
    "options": [{"id": "A", "text": "2"}, {"id": "B", "text": "4"}],
    "answers": ["A"]
  },
  {
    "id": "b2", "chapterId": "chapter-1", "type": "B", "num": 4,
    "stem": "2+2的结果是？", "groupId": "sum-group",
    "options": [{"id": "A", "text": "2"}, {"id": "B", "text": "4"}],
    "answers": ["B"]
  }
]
```

B型题开启选项乱序后，同组使用同一份选项顺序；A3/A4各题选项独立乱序。

## 5. 选项乱序与答案字母

判分始终使用源选项ID，不改写题库中的answers。界面按照本轮显示位置重新标A、B、C……，用户点击和快捷键会映射回源选项ID。

例如源答案为B、D，乱序后正确内容可能显示为A、C。此时选择屏幕上的A、C即可答对。反馈使用当前显示字母；错题本和搜索结果使用题库原始字母与完整文字，便于对照原资料。不能只凭显示字母不同判定答案错位。

## 6. 新增一门课程：完整步骤

1. 复制 `templates/new-course.js` 到 `data/courses/`，例如命名为 `physiology.js`。
2. 将JS容器键、course.id均改为 `physiology`，修改title、description、version。
3. 编写章节与题目，删除模板示例，保持题目ID唯一、章节引用有效。
4. 在 `data/catalog.js` 注册课程ID：

```javascript
window.QUIZ_COURSE_CATALOG = [
  "preventive-medicine",
  "physiology",
  "format-demo"
];
```

5. 在index.html的题库脚本区域增加：

```html
<script src="./data/courses/physiology.js"></script>
```

此标签位于catalog.js之后、engine.js与app.js之前。课程ID在catalog中出现但文件没有加载时，该课程会被拒绝加载，并显示错误提示。

6. 运行校验：

```bash
node tools/validate-banks.cjs
```

7. 本地打开index.html，确认课程下拉菜单、章节、题型计数正确。体验普通模式、快刷、多选提交后，再上传文件到仓库。若已打开旧页面，刷新后再核对。

如果使用纯JSON模板编辑，可先单独检查：

```bash
node tools/validate-banks.cjs templates/new-course.json
```

完成后将JSON对象放进上文的JS容器包装中，再按步骤4、5注册。无需修改核心答题代码。

### 移除示例课程

同时删除catalog.js里的 `format-demo` 和index.html里的 `format-demo.js` script标签即可。可以保留示例文件作为维护参考，它不会自行出现在课程菜单中。

## 7. 更新已有题库

- 只修改课程文件即可更新题目，题库总数自动变化。
- 新增章节：先在chapters添加定义，再把题目的chapterId指向该ID。
- 题型数量只统计当前选中的章节，与题型是否勾选无关；下方总筛选题数则同时考虑章节和题型。
- 0题的题型仍显示，用户之前的题型勾选不会因为切换章节而被清空。重新选择有题的章节后仍按原勾选练习。
- 原题目ID应保持稳定。新增题目采用新ID，不能复用已删除题目的ID。
- 更新课程version便于维护追踪；小版本变化不会清空学习记录。修改某题答案不会自动重算已保存的旧作答，重新作答后会更新它的最近结果。
- 删除题目后，统计和错题本会排除失效ID。
- 章节、题型、选项、题库脚本全部区分大小写。

## 8. 字符与排版规范

所有文件保存为UTF-8。题库字段均为纯文本，不接受富文本或Markdown渲染。`\n`可用于共用材料和解析的换行；题干使用pre-wrap保留换行，选项按浏览器自动换行。

以下规则尤其重要：

- 引号必须为JSON双引号，字符串内部双引号用 `\"` 转义。
- 多选答案必须是数组 `["A", "C"]`，不是 `"AC"`、`"A,C"` 或 `"A C"`。
- 单选也必须使用数组，如 `["B"]`，不能再使用旧字段answer。
- 稳定选项ID放在id字段中，选项内容放在text字段中，不能在选项文字里重复写答案字母。
- A3/A4的共用病例放sharedStem，不要只放在组内第一题中，否则随机抽题时会丢失上下文。
- B题同组复制完全相同的options数组，不能把下一组的选项误配给上一组题。
- 保留上下标、希腊字母、温度、百分号、正负号和计量单位。`Pa`与`μPa`不等价，`10⁶`与`10⁻⁶`不等价。
- 答案页缺失或存在争议时应先核实。格式校验只能保证结构有效，不能保证题干、医学答案或参考资料本身正确。
- 当前版本不支持“无标准答案”的练习题；不要编造一个答案以通过校验。

## 9. 校验与常见错误

网站启动时检查各课程；格式错误的课程不加入下拉菜单，其他有效课程仍可使用。校验工具会把错误定位到questions的数组下标，例如 `questions[87]` 指第88条数据，不一定等于原题号88。

| 错误 | 常见原因 | 修改方法 |
| --- | --- | --- |
| 答案不在选项中 | 答案字母写错或选项漏录 | 核对源资料，恢复选项或答案ID |
| 单选必须恰有一个答案 | 单选写了多个答案 | 核对是否应改为X型；不可仅删掉其他答案 |
| X型至少两个正确选项 | 把单选错误标成X或漏录答案 | 核对题型及完整答案 |
| 选项须含2–10项 | 原文抽取失败或误把所有内容挤在一项 | 按源资料逐项拆开 |
| ID重复 | 从模板复制题目后未改id | 使用新的唯一ID |
| 找不到所属章节 | chapterId拼写错误或章节定义缺失 | 修正引用或补充章节 |
| B组备选答案不一致 | 同组漏项、改顺序或误用了groupId | 对照原文统一同组选项 |
| 同组sharedStem不一致 | 组内某题漏了病例、换行不同 | 复制相同共用材料，或核对是否属于不同组 |
| 未知字段 | 写成answer、option、chapter等旧字段 | 使用本文定义的规范字段 |
| schemaVersion错误 | 把字符串写成数字或版本不支持 | 使用字符串 `"1.0"` |

JSON Schema适用于编辑器辅助，但ID唯一、章节引用、答案属于选项、B组一致性等跨字段规则仍需执行本包校验工具。工具不依赖额外npm包，需电脑已有Node.js。

## 10. 学习记录与旧版迁移

新版本按课程ID分别保存进度、错题、标记与设置。切换课程不混合记录，重置只清理当前课程。记录只存在当前浏览器、当前网站来源中，不会在电脑、手机或不同浏览器之间自动同步。

对旧版的 `quiz_progress_v1`、`quiz_wrong_v1`、`quiz_mark_v1`、`quiz_setting_v1` 做一次性迁移，仅迁入预防医学课程。迁移后保留旧键，不覆盖已有v2记录。前提是升级前后使用同一网站来源、同一浏览器。

WorkBuddy地址和GitHub Pages地址不同，不能自动读取对方的记录。导出功能按课程产生JSON备份，当前版本尚无导入按钮，导出的文件可以留作后续恢复工具的数据来源。
